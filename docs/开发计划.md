# Mini Coding Agent 开发计划

> 依据：《深度学习》课程期末考核要求（PDF 原文）
> 目标产出：一个可运行的 Coding Agent（60 分课堂实测）+ 一份 40 分期末报告
> 硬约束：个人独立完成 · DeepSeek 官方 API · 普通 CPU · 命令行即可 · 考前冻结版本

---

## 0. 三条总原则

1. **能跑 > 花哨。** 课堂 60 分全靠"实跑结果"，任何在考场机器上装不起来、跑不通的设计都是负分。
2. **能解释 > 高大上。** 报告要"结合本人代码"，架构越简单、你自己越熟，答辩越稳。用 while 循环 + 工具字典写主循环，不要上 LangGraph。
3. **日志 = 分数。** 执行日志既是 60 分课堂的"可核验性"证据，又是报告 10 分"系统测试与验证"的素材。从第一行代码就要记。

## 2. 第一步：确认与骨架（预计 2～3 天）

### 2.1 开工前必须问老师的三件事（用默认假设先往下做）

| 问题 | 默认假设（问不到就按这个做） |
|---|---|
| 课堂上有网络吗？ | 有，但不稳定 → 必须做重试 + 缓存式"断点续跑"降级 |
| API 费用谁出？ | 自己出 → 加 token 预算上限，超了主动收敛 |
| 冻结版本怎么交？ | git tag + zip 双保险，考前当晚打包 |

> 还有：考试日期、时长、三道题的测试接口/运行命令/数据格式。这些不改变架构，但影响你在考场上的操作 SOP（第 7 节）。

### 2.2 环境搭建（一次做对）

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -U pip
pip install openai python-dotenv rich tenacity pydantic loguru numpy pandas scikit-learn pytest
pip install torch --index-url https://download.pytorch.org/whl/cpu
```

- Windows 终端设 UTF-8：`$OutputEncoding = [Text.Encoding]::UTF8`，避免中文日志乱码。
- 装完立刻跑 `scripts/smoke.py`：能调用一次 API、能 `import torch`、能跑一次 pytest，三件事都通才继续。

### 2.3 核心模块的职责边界（写代码前先定死，后面不改）

**`config.py`**
- 从 `.env` 读 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`（默认 `deepseek-chat`）
- 可调参数：`temperature=0.2`、`max_steps=25`、`exec_timeout=30s`、`max_tokens_budget=200000`
- 全部有默认值，**不依赖交互输入**（考场上没人有空填参数）

**`llm.py`**
- 用 `openai` SDK，`base_url="https://api.deepseek.com"`
- 封装三件事：重试（`tenacity`，3 次指数退避，只对超时/429/5xx 重试）、用量统计（累计 prompt/completion tokens）、异常归一化
- 返回结构统一成 `{content, tool_calls, usage}`，主循环不关心底层

**`tools/`**（6 个工具，JSON Schema 定义的 description 要写细，这是报告 10 分里"工具调用"的实证）

| 工具 | 关键设计 |
|---|---|
| `read_file(path, start?, end?)` | 支持行号窗口，避免一次读整个大文件 |
| `write_file(path, content)` | 整文件写入，自动建父目录 |
| `replace_in_file(path, old, new)` | 精确字符串替换，找不到就报错——**改代码优先用这个**，省 token |
| `list_dir(path)` | 返回文件名 + 大小，递归一层 |
| `run_python(path, args?, timeout?)` | subprocess，捕获 stdout/stderr/exit code，**强制超时** |
| `run_pytest(path?, timeout?)` | 跑测试并解析结果（收集通过/失败/错误行的摘要） |

所有文件工具 **限定在 `runs/<id>/workspace/` 内**，用 `resolve()` 校验路径前缀，防越界。

**`exec.py` 的三个必做细节**
1. 超时用 `subprocess.run(timeout=...)`，超时后 `kill` 整个进程树（PyTorch 训练会挂子进程）
2. 输出**先截断再返回**：保留头 60 行 + 尾 40 行，中间写 `... truncated N lines ...`。否则一次 traceback 就能吃掉几万 token
3. 环境变量里显式 `PYTHONIOENCODING=utf-8`，并 `cwd` 设为该次运行的工作目录

**`context.py`**（报告"上下文管理"的正面材料）
- 只保留最近 12 条消息 + 首条任务描述
- 超长工具结果按"头尾截断"处理
- 超预算时对早期轮次做**摘要压缩**（让模型自己总结"已尝试过什么、失败在哪"），而不是硬截断

**`logger.py`**
- `trace.jsonl`：每行一个事件，字段 `{ts, step, event, tool, args, result_summary, tokens, elapsed}`
- `agent.log`：人类可读版，课堂演示和报告截图用这个
- **脱敏**：写盘前用正则 `sk-[A-Za-z0-9]{10,}` 替换成 `sk-***`；`args` 里出现 `api_key` 一律遮蔽
- 这是纪律要求："不得在日志中暴露 API Key"

### 2.4 主循环（先写伪代码，再写实现）

```
messages = [system_prompt, task_prompt]
for step in 1..MAX_STEPS:
    resp = llm.chat(messages, tools=TOOL_SCHEMAS)
    log_event(step, resp)
    if resp.tool_calls:
        for call in resp.tool_calls:
            result = dispatch(call)          # 含异常兜底，工具报错也返回给模型
            messages.append(tool_result(call.id, truncate(result)))
        messages = context.trim(messages)
    else:
        # 模型只回文字：判断是"解释"还是"完成"
        if is_finish_intent(resp.content): break
        messages.append(user_hint("请继续使用工具推进任务，或调用 finish 结束"))
    if budget_exceeded(): break
```

三条硬性规则：

- **全自动，不中途问人。** 考场规则只允许"启动程序 / 给任务 / 配参数 / 展示结果"，任何 `input()` 确认都会踩线且浪费时间。默认自动批准所有工具调用。
- **必须能终止。** `finish` 工具 + 最大轮数 + 预算上限，三重保险。
- **工具报错不是崩溃。** 把错误信息当正常结果喂回模型，让它自己纠错——这正是"根据运行错误自动尝试修正"的评分点。

### 2.5 CLI 入口（考场就看这一条命令）

```powershell
python -m agent.main --task-file task.txt --workdir auto
```

- 输出：实时打印每步动作（`rich` 美化），结束后打印 `runs/<id>/` 路径
- 结束前自动落盘：最终代码、日志、用时、token 消耗
- **无任何交互式提问**

## 3. 第二步：三道模拟题压测（预计 3～4 天）

**这一步是整个计划里性价比最高的部分。** 模拟题直接按真实题型的三个层次来出，它同时产出三样东西：

- 告诉你 Agent 在哪一层崩（功能缺陷 / 提示词缺陷 / 上下文缺陷）
- 生成报告里"至少一个完整执行案例"的素材
- 构成报告 10 分"系统测试与验证"的全部内容

### 3.1 模拟题设计

| 文件 | 题型 | 自建评测标准 |
|---|---|---|
| `eval/task1_data_structure/` | 给一份接口说明（如"实现 LRU Cache：get/put/容量、空容器、重复 key 更新"），要 Agent 从零写实现 | 隐藏 pytest 用例 10～15 条，覆盖正常 + 边界（空、重复、容量为 1） |
| `eval/task2_bugfix/` | 教师式源码：一个 pandas/numpy 小脚本，**人为注入 4～5 个 bug**（标准化用错 axis、reshape 维度、int/float 溢出、空输入未处理、off-by-one） | 指定缺陷的定向测试 + **原有功能回归测试**（这条对应评分"确保原有正确功能不受影响"） |
| `eval/task3_mlp/` | 给 `train.csv`（带标签）+ `test_features.csv`，要求产出一个指定格式的 `predictions.csv` | 用保留标签算 accuracy，设定通过阈值；同时记录训练耗时，确保 CPU 上跑得完 |

任务三的模拟数据集自己造：三类、几百条、几个数值特征即可，重点是**流程跑通**而不是刷精度。

### 3.2 每次压测记录的指标

| 指标 | 含义 | 期望 |
|---|---|---|
| 是否完成 | 终态是否产出可运行的正确程序 | 三题都要 100% |
| 轮数 | 主循环迭代次数 | 任务一 ≤ 8，任务二 ≤ 12，任务三 ≤ 15 |
| token | 总消耗 | 任务三最贵，设单次上限 |
| 耗时 | 墙钟时间 | 必须 < 考场时限的 50% |
| 失败模式 | 崩在哪一类（读文件错 / 测试输出太大 / 改代码越改越乱 / 训练超时） | 归类后针对性改提示词 |

失败模式要**记下来**，报告"结果分析与总结"里"成功与失败原因"就是从这张表长出来的。

### 3.3 迭代优先级（改什么、按什么顺序改）

1. **先修工程问题**：超时、输出截断、路径、编码、重试 —— 这些是"能不能跑"，优先级最高
2. **再修提示词**：system prompt 里明确"先读需求 → 先写最小可运行版本 → 跑测试 → 根据报错定向修"；明确"不要一次写几百行"
3. **最后调参**：模型、温度、最大轮数。**在最后调**，因为前两步没做完时调参等于瞎调

压测每轮都要跑 `scripts/grade.py`，把结果写进 `runs/eval-report.md`，这份文件最后直接改写成报告第 3、4 节。

| 4 系统测试与验证 | 2.5 | 系统测试与验证 | 三道模拟题的测试方案、指标表、**一个完整执行案例**（任务输入 → 工具执行 → 测试反馈 → 最终结果，用日志里的真实片段） |

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 考场断网/限流 | 直接崩 | 重试 + 指数退避；考前问清网络；极端情况准备"离线演示"录屏 |
| API 余额不足 | 直接崩 | 考前充值并跑一次完整压测确认额度够 |
| 依赖缺失（torch/pandas） | 任务二三跑不了 | 考前在考场同款机器上跑 `smoke.py`；`requirements.txt` 锁定版本 |
| 模型跑偏，越改越乱 | 轮数爆炸 | 提示词加"每轮只改一处""改坏了先 git 回滚（工作目录内）"；最大轮数硬限制 |
| 训练超时（任务三） | 25 分丢 | 提示词约束：小 MLP、≤ 20 epoch、`torch.set_num_threads(4)`、数据规模小 |
| 日志泄露 API Key | 纪律处分 | 写盘前正则脱敏 + 提交前全局搜 `sk-` |
| 被判定"封装现成 Agent" | 成绩无效 | 架构与代码全部自写；README 里说明每个模块自己实现 |
| 报告只堆概念 | 40 分里大量失分 | 严格按 4.2 的结构，每节都必须有本人代码/日志/数据 |

## 7. 考场执行 SOP（打印出来带进去）

**考前 10 分钟**
1. 激活虚拟环境，跑 `python scripts/smoke.py` 确认 API 通、依赖在
2. 打开一个新的 `runs/` 目录，确认磁盘可写

**拿到任务时**
3. 把教师给的任务原文**原样**存成 `task.txt`（用文件，不要手打）
4. 复制教师给的数据文件到 `workspace/`，**不改动原文件**
5. 启动：`python -m agent.main --task-file task.txt --workdir auto`

**过程中（只允许这几类操作）**
6. 启动/重启程序；看日志；把终端输出展示给教师
7. 允许调整运行参数（模型、轮数上限）
8. ❌ 不手写、不手改目标代码
9. ❌ 不改教师给的测试文件、数据、评分输入
10. ❌ 不额外一步步口头提示模型怎么解

**交卷前**
11. 检查三类产物：最终 `.py` 源码、任务三的 `predictions.csv`、完整日志
12. 全局搜一遍 `sk-`，确认无泄露
13. 记录耗时与 token 消耗（报告要用）
